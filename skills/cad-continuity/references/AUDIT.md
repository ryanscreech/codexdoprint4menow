# Operation: audit

Purpose: assess **all accessible project-related sessions** for missed efficiencies and underused findings, with transparent coverage.

## Procedure
1. Confirm project root and permitted transcript roots. Resolve the configured Codex home first (`CODEX_HOME`, otherwise user `.codex`); consider its `sessions/` and `archived_sessions/` within authorised scope, and project-generated handovers. On Windows, inspect PowerShell `$env:CODEX_HOME` and `$HOME\.codex\sessions`. Do not assume a server, macOS or remote host history is accessible.
2. Build a **coverage manifest** before judging completeness. Enumerate JSONL and archived formats supported by environment; capture session ID, timestamp, cwd, topic/artifacts, evidence of project association, and inspection depth. Deduplicate only byte-identical copies by content hash. Keep approval/review forks and same-ID files with different content: they can contain unique corrections or later events. Record their relationships and shared prefixes without dropping unique evidence. Never equate broad keyword matches with confirmed project membership.
3. Use [the indexer](INDEXER.md) to record file hashes and candidate event locations when available. A cwd match is association evidence, not proof that all turns concern the project; a different cwd cannot exclude work done through explicit paths. Reuse a previous index only for unchanged files; recheck new, changed, ambiguous and previously inaccessible candidates. Prefer metadata and compact handovers to classify. Inspect targeted events in *all confirmed related sessions*; list ambiguous/excluded sessions with reasons. For huge files work in bounded chunks.
4. Trace a timeline of tasks and artifacts: repeated datasheet parsing, rebuilt geometry, repeated environment setup, repeated failures, forgotten verification, deprecated methods, uncaptured user measurements, broken handovers, unsafe overwrite, untested fit assumptions and duplicated tooling.
5. Compare what each session discovered against the *next sessions'* actions. Record missed opportunities **with evidence**: was a prior verified STEP available? did later work redundantly reconstruct it? were previous failures repeated? were independent checks run? Were lessons proposed but never adopted?
6. Produce a prioritised audit table: finding ID, sessions, observation, cost mechanism, confidence, evidence location, suggested correction, effort, severity, and verification plan. Avoid imaginary time/token savings; report the last valid cumulative token snapshot with its line reference, not the sum of cumulative snapshots. Cached input is part of input; reasoning output may be part of output. Do not add subset counters twice. Note resets, inherited fork usage, missing counters and schema uncertainty before comparing sessions; never treat missing usage as zero.
7. Compare `cad-knowledge/` to transcript findings. Identify stale decisions, unbounded unknowns, missing hashes, absent next-action handovers and conflicts. Create proposed KB patches; do not auto-apply or change the global Skill without explicit authorisation.
8. Write `cad-knowledge/audits/AUDIT-YYYY-MM-DD-<short-id>.md` (choose a unique name; preserve prior reports) only with write permission. Include **coverage** (total discovered, confirmed, ambiguous, inspected, excluded, inaccessible), next-step plan, and outstanding hosts/archives.
9. State whether result is a **complete accessible-root audit** or **partial audit**. Never say "all project sessions" if only one host was checked.

## Suggested report headings
Scope and sources; coverage manifest; session-to-session timeline; repeat work; verification quality; knowledge gaps; efficiency opportunities; recommended process edits; rejected claims; measurement plan; unresolved access.

## Coverage record

For each candidate record path, session ID, file SHA-256, project-association evidence, related/fork IDs if known, inspection depth (`metadata_only`, `targeted`, `full`), inspected line ranges, disposition and exclusions. Hashes and line references identify the snapshot used; active files can change. Keep malformed/unknown formats and unsupported archives in the manifest and report partial coverage until resolved. Enumeration alone never counts as semantic inspection.
